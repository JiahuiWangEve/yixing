# v0.14.4 调试模式与整局悔棋额度

## 行为

- 首页新增默认关闭的「调试模式」开关；设置独立持久化，Web 同步保存至 localStorage。
- 关闭时不显示跳关按钮，点击旧位置或直接调用跳关逻辑均不能跳关。悔棋仍显示，整局征途共三次。
- 开启时可以跳关，悔棋不限次数；仍只保留最近三回合的行动历史。开启期间不消耗正常额度，开关往返不补充额度。
- 额度跨战斗及章节保存，继续存档保留，新征途重置三次。旧 v5 存档缺省三次，不变更旧存档版本号。
- 额度不放入 undo 快照；成功悔棋后才扣除并立即保存。无历史、教学、动画锁、导航锁或覆盖界面时不扣；Ctrl+Z 共用相同守卫。
- 调试跳关复用正常胜利、奖励及呈现流程，不重新开放旧选关入口。

## 验证

- Godot 4.6.3 全量 `scripts/verify.sh` 通过，包括所有原有回归及新增38项 `debug_undo_checks.gd`。
- 原规则测试明确开启生产设置，并在模拟动画结束后执行悔棋，不放松游戏侧输入守卫。
- 全部 browser 检查通过正常设置存储显式启用调试，首次安装后不会覆盖重载期间的用户切换。
- `browser_release_smoke.py` 无存档注入，通过首页开关开启调试。
- 新增 `browser_debug_undo_checks.py`，真实桌面及触屏 UI 覆盖默认OFF、隐藏跳关、三次额度、键盘守卫、刷新保留、ON重复悔棋、切回OFF不补额度；纳入Web发布门禁。
- 已完成脚本语法检查及 Web 导出；本地浏览器执行被 Chromium socket 权限阻止，真实 Web 结果需以 CI 或独立 GUI 环境执行为准，不将未运行项目记为通过。

- 强化动画的 Web 证据改为输入前启动合成器逐帧采集，并以卡面实际纸色区分完整旧牌与强化牌，断言顺序及两阶段均存在；不再以两张可能越过动画的延时截图差分冒充前后捕获。待 CI 验证。
